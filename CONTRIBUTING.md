# Help make Pocket better

[English overview](README.md) · [Описание по-русски](README-RU.md)

Useful contributions include reproducible bug reports, device feedback, clearer documentation, accessibility improvements and small focused fixes. Start with [an issue](https://github.com/RadmirAmir/pocket-llama/issues/new/choose) describing the problem or idea. Include your phone, Android version, app version, selected model and backend when they matter.

Use synthetic recordings and documents when reproducing a problem. Public issues and pull requests must not contain personal content, PINs, access tokens, signing keys or model files with incompatible redistribution terms. Documentation previews are illustrative and should be labeled as such.

For code changes, follow [the build guide](docs/BUILDING.md), keep a pull request focused and explain the behavior before and after your change. Run the checks relevant to the changed area and describe what you verified. Physical-device feedback should clearly distinguish observations from estimates; host tests do not establish phone performance.

The project's own code is Apache-2.0. Check [the component inventory](docs/LICENSING.md) before adding dependencies or models. Use the same license for original contributions to the app; third-party components retain their own terms.

## По-русски

Помочь можно сообщением об ошибке, проверкой на своём телефоне, улучшением инструкций и доступности или небольшим исправлением. Опишите задачу в issue, затем предложите отдельный понятный PR. Укажите, что изменилось и как это проверено. Для сборки есть [инструкция](docs/BUILDING.md).

В публичных материалах используйте вымышленные данные. Не загружайте личные записи и документы, PIN, токены, ключи подписи и веса с неподходящими условиями распространения. Замеры на реальном телефоне отделяйте от предположений.
